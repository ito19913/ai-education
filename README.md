# AI-Education

中2の娘さん向け、「勉強の仕方そのもの」を変える学習ツール。

## このプロジェクトの真のゴール

教科の点数を上げる事でも、学習習慣をつけさせる事でもない。**「暗記モードから、知識をツールとして使うモードへ」** という勉強観の転換を娘さんに体験させる事である。

その本丸は [PHILOSOPHY.md](./PHILOSOPHY.md) に書いてある。**実装の前に必ず読む**。すべての設計判断はここから派生する。

## 一文で言うと

> PC/タブレットに向かって話すだけで、頭の中に「ツールセット」が組み上がっていく音声対話型の学習ツール。

紙も鉛筆もいらない。「机に向かう作業」もしない。AI と会話する中で、知識を自分の言葉で組み替え、整理し、引き出せる状態にする。

## 機能の階層構造

| 階層 | 機能 | 範囲 | フェーズ |
|---|---|---|---|
| 土台 | 言葉の意味の正確な理解（単語確認ツール） | 全教科共通 | 1 (MVP) |
| その上 | 体系の骨格を掴み、ツール化する | 教科別（MVP は中2英語文法） | 1 (MVP) |
| さらに上 | 体系の上で個別の道具を使いこなす（応用） | 教科別 | 1 (MVP) |
| 診断層 | **テスト/課題フィードバック（認知プロセス診断）** | 教科別 | **2** |

「文章が頭に入らない」の根本原因は、構成する日本語の単語の意味が曖昧なまま記憶しているから。単語確認が土台にないと、その上の体系化もツール化も成立しない。

下位 3 層（フェーズ 1）は「ツールを組み立てる」段階。診断層（フェーズ 2）は「組み立てたツールがちゃんと取り出せたか/使えたかを診断する」段階。両者がペアで初めて完結する。

## 体験フロー（毎セッション）

1. **事前準備**（ito19 さんが管理画面で）: 教科書を PDF 化してアップロード、AI が体系図を初期生成 → ito19 さんが監修
2. **フィロソフィー確認の儀式**: 「勉強とは何か」を AI が短く語る。毎回必ず
3. **位置確認の儀式**: 体系図上で「今、全体のここをやっているよ」を上から階層構造で示す
4. **今日の範囲申告**: AI が「今日は何ページから何ページまで？」と問い、娘さんが音声で答える
5. **対話学習**: AI が「これ理解できる？」と問い、娘さんが音声で答える
6. **理解の判定（ファインマン式）**: 「自分の言葉で説明してみて」。詰まる箇所が単語確認への自然な導線
7. **ツール化**: 娘さんが AI と対話しながら、文法項目を「何をするツールか・いつ使うか・例文」として自分の言葉でカード化
8. **記録と反復**: 間違い・理解不足を AI が記録、1 週間後・1 ヶ月後・テスト前にリマインド

## ロール分担

- **ito19 さん（管理者・伴走者）**: PC から管理画面にアクセス。教科書 PDF アップロード、AI が生成した体系図の監修、進捗確認。娘さんとの会話でも同じフィロソフィーを使う
- **娘さん（学習者）**: 新規購入タブレットから学習画面にアクセス。音声対話で学ぶ
- **AI（伴走相手）**: 体系図の初期生成、対話相手、ツールカード作成支援、フィロソフィーの繰り返し提示、記録、反復リマインド

## MVP の範囲

最初に作るのは **中2英語文法の 1 単元のみ**。ただし体験フローは **全 8 ステップ全部入り**。

1 単元の体験を磨き切ってから、機械的に他単元・他教科へ展開する。「広く浅く」は絶対 NG。

詳細は plans/home-ai-educarion-merry-kazoo.md を参照。

## フェーズ 2 展望: テスト/課題フィードバック機能

日常学習（フェーズ 1）が成立したら、その上に **テストフィードバック層** を乗せる。

- **目的**: 返却されたテストや解いた課題を、点数ではなく「**自分の認知のどこで詰まったか**」を発見する対象として扱う
- **投入方法**: 娘さんがタブレットで撮影 → AI マルチモーダル処理（その日のうちに壁打ち開始できる即時性を優先）
- **フィードバック分類**: 5 観点（言葉が曖昧 / 理解していなかった / 整理できていなかった / 使い方を知らなかった / 気づかなかった）
- **設計の核**: 「思い出せなかった」というフィードバックは **意図的に出さない**。それ自体が暗記モードの発想だから

詳細は [PHILOSOPHY.md の「テストや課題への向き合い方」](./PHILOSOPHY.md#テストや課題への向き合い方) を参照。

## 技術スタック（確定）

| 層 | 選定 |
|---|---|
| フレームワーク | Next.js 16 + React 19 + TypeScript strict |
| UI | shadcn/ui (base-nova / @base-ui/react) + Tailwind v4 |
| LLM | **Claude Opus 4.8**（Anthropic SDK） |
| 音声入力 (STT) | ブラウザ標準 Web Speech API（無料） |
| 音声出力 (TTS) | OpenAI TTS（gpt-4o-mini-tts） |
| DB / Auth / Storage | Supabase（PostgreSQL + Auth + Storage、RLS で家族のみアクセス） |
| ホスティング | Vercel（Hobby プラン、無料） |
| テスト | Vitest |
| 雛形 | `workspace-ui-kit/` → `web/` にリネームして本体化 |

**インタラクション方式**: Push-to-talk 一括方式（音声 → Web Speech API でテキスト化 → Claude → OpenAI TTS で読み上げ + 補助テキスト表示）。応答 3〜5 秒の遅延は許容。

**月額ランニング目安**: 3,000〜5,000 円程度（Claude API + OpenAI TTS、利用頻度次第）

## 起動方法（開発）

### 前提
- Node.js / npm
- Supabase アカウント + ai-education プロジェクト
- Resend アカウント（メール送信用、無料枠で十分）
- `web/.env.local` に Supabase / Resend のキーが設定されていること

### 手順
```bash
cd web
npm install        # 初回のみ
npm run dev        # 開発サーバー起動
```

- PC ブラウザ: http://localhost:3000
- 同一 LAN のタブレット: http://192.168.x.x:3000（IP は `npm run dev` の出力で確認）
- 未ログインなら自動で `/login` へリダイレクト
- マジックリンクログインで認証

### 利用可能なルート

| ルート | 内容 |
|---|---|
| `/login` | マジックリンクログイン |
| `/` → `/tutor` | ログイン後の自動着地 |
| `/tutor` | **担任「ゆい」さん chat（リッチカード埋込、Phase 2 mock）**。会話 → 教科 → 教材 → 体系図プレビュー → 学習開始 |
| `/schedule` | 学習スケジュール ダッシュボード。試験まで / 未クリア課題 / 今週の予定 + 今日のタスク + 2 週間ミニカレンダー + 4 task type 登録パネル |
